1. Project Objective & Scope

The primary objective of Mumbai Commute Analytics is to build an empirical, beginner-friendly Data Science pipeline that models urban commuting patterns across Mumbai's three dominant transit modes: Mumbai Metro, Mumbai Suburban Local Train, and Auto Rickshaw.

By examining transit metrics including travel time, fare cost, distance, waiting time, peak-hour bottlenecks, crowd levels, and weather delays, this system demonstrates end-to-end Data Science workflows: data generation, cleaning, exploratory data analysis (EDA), explainable machine learning classification, and web dashboard deployment.

3. Dataset & Project Limitations

Mandatory Academic Disclaimer: "This dataset is created/simulated for academic analysis and does not represent official Mumbai transport statistics."
Why Simulated Data?

Official, granular trip-level datasets containing simultaneous waiting times, delays, costs, and passenger crowd ratings for individual transit riders across Mumbai are proprietary and not publicly available in open data formats. Hence, a realistic 1,200-sample academic simulation was generated using verified Mumbai geography.

Key Limitations:
  • Does not include multi-modal transit (e.g. Walking + Auto + Train).
  • Dynamic surge fares (e.g. ride-hailing aggregators) are excluded; standard Mumbai auto meter pricing rules are applied.
  • The ML model reflects patterns within this specific dataset and should not be used as an official municipal planning engine.

Essential questions commonly asked by external college examiners for B.Sc Data Science projects.

Data Science is the interdisciplinary field that uses statistical methods, scientific processes, and algorithms to extract actionable insights from data.
Our Lifecycle: Data Collection/Simulation → Data Cleaning & Preprocessing (Pandas) → Exploratory Data Analysis & Visualization (Seaborn/Matplotlib) → Feature Engineering → Model Training & Evaluation (Decision Tree in Scikit-learn) → Deployment (Flask Web App & Power BI Dashboard).

Raw data in the real world is messy. In our project, the raw dataset contained:
  1. Duplicate rows: Identified and removed using df.drop_duplicates().
  2. Inconsistent text casing: Standardized 'metro', ' Local ', 'auto rickshaw' into clean canonical labels ('Metro', 'Local', 'Auto').
  3. Missing values (NaN): Imputed missing Waiting_Time_min with the mode/median of the respective transport mode, and missing Crowd_Level using mode.
  4. Impossible / Anomaly values: Filtered out impossible negative travel times, negative costs, or distances > 70 km.

A Decision Tree Classifier is simple, intuitive, and highly explainable (white-box model). Unlike complex black-box deep neural networks, a Decision Tree creates transparent if-else decision rules based on thresholds like distance and cost that human examiners and commuters can easily interpret.

Train-test split partitions our dataset so that the model is trained on one portion (80%, 956 samples) and tested on an unseen portion (20%, 239 samples). This prevents overfitting and allows us to verify whether the model can generalize accurately to new commute trips.

A Confusion Matrix is an $N \times N$ evaluation grid comparing the model's predicted classes against actual ground-truth classes. The diagonal elements represent correct predictions (True Positives), while off-diagonal elements show classification errors (e.g., misclassifying an Auto trip as a Metro trip).

Flask Dashboard: An interactive custom web application built with Python and HTML/JS that directly runs our real-time Scikit-learn Machine Learning inference form.
Power BI Dashboard: A dedicated Business Intelligence tool designed for enterprise reporting, drag-and-drop slicing, multi-dimensional DAX calculations, and interactive executive reporting.
